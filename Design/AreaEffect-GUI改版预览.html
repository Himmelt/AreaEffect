改动说明

  • 维度 → tab 条：原来的左栏（12%）取消，维度以 18px 高的 tab 条横排在内容区上方，选中项与原选中色一致（半透明青）。tab 条宽度按文字实测，只有总宽超出可见宽度时才出现两侧 < >；到达两端时按钮转灰不可点，不需要翻动时两个按钮整块隐藏（腾出宽度）。
  • 框线共用：整块外框只有 1px，tab 条与内容区共用一根横线，三栏之间共用一根竖线，两个工具按钮共用一根分割线 —— 相邻元素不再各画一圈边框。为在深色背景上看清，预览里线色由实值 #4A6666 提亮到 #86A6A6，实际绘制仍用原色。
  • 默认配比按"内容需要"定，不是把原四栏等比放大：按原比例归还 12% 的结果是区域栏 102px（备注只剩 66px ≈ 6 个汉字）而详情栏 225px 里内容只占上 96px。26 : 22 : 40 是反推出来的 —— 区域栏每行都要放 #id + 备注（信息密度最高），详情栏只有 4 条滑条（够放最长文案即可），效果栏够放「名称 + W 值」即可。滑杆按权重生效（不必凑满 100），右侧实时显示折算占比与像素宽；两个预设按钮可一键对比新默认与旧基准 20 : 24 : 44。
  • 时段滑条文案压缩（它决定了详情栏的宽度下限）：原 生效时段: 游戏时间 06:00 → 18:00 实测 186px，逼着详情栏必须 ≥46% 才不裁字，右栏因此缩不下来。压成 时段 游戏 06:00→18:00（约 121px）后详情栏能收到 40% 以下。模式全名只留在状态栏提示语里（"时段模式轮切为「游戏时间」"），需要时再给 gui.areaeffect.edit.timeMode.* 补一组短名文案。
  • 删除按钮隔离：四个图标原来等距 3px，而删除是唯一不可逆的动作（onDeleteRequest 立即落盘 + 广播），误点代价最高。现在把它移到按钮组最左、右侧留 10px 空档，悬停用红（#FF6B6B）而非黄，与三个安全动作在空间和语义上分开 —— 同时最常用的「保存」仍在最右端。
  • 区域级的东西全搬到底栏：备注编辑、传送、删除、线框、保存本来分散在「区域列表行内图标」和「右栏顶部」两处，且都和别的东西混在一起。现在把 L2（区域级）整体收进窗口底栏一条 22px 的「区域操作条」，元素全部按固定尺寸/位置排：#id · 形状名（固定 104px 槽位，超出省略号）· 备注输入（占满剩余宽度）· 未保存圆点 · 传送 / 删除 / 线框 / 保存四个 18×18 图标（固定 3px 间距、整体贴右边界）。底栏横跨三栏、又贴着整个面板的下边界，正好表达"作用于当前选中的区域"这件事。
    备注框左边界对齐「区域列 | 效果列」那根共用竖线：做法不是给输入框设一个固定左边距，而是反过来算 #id 槽位该多宽 —— 槽宽 = 区域列宽 − 15，于是"槽位右沿 + 8 + 8"正好落在竖线上。区域列宽随三栏比例实时变化，所以每次渲染都重算；写死 104px 的话比例一调就错位。备注框左边界对齐竖线后，它跨越的正好是效果与详情两栏。
    保存改用 ✓ 图标与其余三个同规格 —— 图标式的好处是四个按钮尺寸一致、可以整体右对齐，不必为一个文字按钮留 54px 的宽槽；未选中区域时四个图标整体转灰而不是消失，避免布局跳动。有未保存改动时只有 ✓ 变黄。
  • 右栏只放参数：栏内不含任何 L2 内容（无 #id、无形状、无备注、无保存），也不再自报"是什么效果"——效果列表的选中行已经表明了，标题属于重复信息。整栏就是该效果的参数：权重、亮度、过渡时长、生效时段。作用的区域由左栏选中行 + 底栏 #id 指示，作用的效果由中右栏选中行指示：同一个「选中项即作用域」的规则，不需要在栏内再写一遍。形状完整坐标范围移到 #id 的悬停提示里，不占宽度。
  • 区域列表行也不再给图标留位：三个图标搬到操作条后，原代码里那段给选中行预留右侧宽度的逻辑（rightPad += (ICON_S + ICON_GAP) * 3 - ICON_GAP + 4）可以直接删掉，备注文字能显示得更全。
  • 编号列右对齐：#id 占一个定宽槽位并右对齐，备注仍左对齐紧接其后 —— 这样所有备注从同一个 x 起，扫读时是整齐的一列。槽位宽度按本维度里最宽的编号实测得出（预览用 canvas measureText，实机用 fontRenderer.getStringWidth("#" + maxId)），所以切换维度、编号位数变化时备注列左边界都不会左右跳。不能按字符数估算：#3 与 #45 差 6px，累积起来就是错位。
  • 顺带补上形状范围：AreaShape#describeKey()/describeArgs() 与语言文件里的 gui.areaeffect.desc.* 早已写好（注释明确写着"详情页展示文案"），但全项目没有任何调用方——上段的形状范围就是把这条现成的挂点接上，正好填掉右栏那片空白。
  • 零效果的保存路径：效果全部删掉后区域只剩备注可改，但保存按钮仍然在、仍然可点 —— 它与「添加/删除效果」不同级：保存属 L2（只要选中了区域就可用，实机 syncDetailWidgets 里 btn.enabled = has），增删效果属 L3。服务端也允许空效果集（AreaRequests#onSetProps："效果集已允许为空（区域可以不带任何效果）"），保存后区域照旧存在，形状/备注/线框/传送都在，只是不再产生亮度效果。为了让"删完还没保存"这件事看得见，预览里把本来就存在、却从未上屏的 GuiAreas#dirty 接到了保存按钮上：有未保存改动时按钮转黄、控制栏出现提示。
  • 为什么保存也属于底栏：它的门控是 L2（选中区域即可用，btn.enabled = has），而一次提交覆盖的是备注（L2）与整份效果工作副本（L3/L4）—— 门控在区域级、作用域是整栏，所以它是区域级动作。放进任何一栏内部都会被误读成"只保存这一段"；摆在横跨三栏的底栏才是诚实的表达。实测代价：底栏占 22px 栏高，三栏内容区从 196px 变成 196px（底栏吃的是原本空着的 30px 页脚带），所以列表可见行数一行没少。
  • 对比选项：控制栏可切「区域级操作 → 详情栏内（原方案）」，看备注+保存留在右栏、三个图标留在列表行的旧样子。当时的取舍：图标挤占列表行宽度、备注与效果参数混在一栏，层级归属要靠分区标题去补。
  • 交互与真实实现一致：编辑写在「工作副本」上、不动共享数据，点保存才回写；添加效果 在可添加类型全部挂载时禁用；时段控件拖游标改区间、点非游标区域轮切模式；行内三图标仅选中行显示、悬停变黄。

默认宽度 480 就是 1080p 下「自动」GUI 缩放的实际值，此时 10 个维度放不下，两侧翻动按钮已经出现；把宽度加宽到约 520 以上就放得下，按钮整块隐藏。
