# AreaEffect 新效果候选清单

> 调研日期：2026-09-18 ｜ 来源：联网调研同类模组 + **逐条回本地 1.7.10 反编译源码核实**（`build/rfg/minecraft-src/java`）
> 用途：挑选下一批要加的区域效果。每项都标了实测可行的钩子、主观成本/收益，勾选框供直接圈定。

---

## 一、结论摘要

- 当前模组已用掉 4 条钩子：`LightmapHook`（亮度）、`FogColors`/`FogDensity`（雾）、`setSkyRenderer`（天空）、`addEffect`（尘粒）。
- **最大的新发现**：1.7.10 自带完整的**后处理着色器框架**，且入口是可控的 —— 一整类"滤镜/扭曲/描边"效果因此可行，不需要 OptiFine。
- **最省力的三个**（都复用现有骨架）：光照贴图色调、氛围粒子、云层接管。三个一轮就能落地。
- 需要用户先定范围的两件事：是否接受**非画面效果**（环境音），是否接受**与 OptiFine 光影互斥**的效果（着色器类）。

### 推荐路线

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| 第一轮 | 光照贴图色调 + 氛围粒子 + 云层接管 | 全部复用现有骨架，风险低，一轮出 3 个效果 |
| 第二轮 | 暗角与全屏叠加 + 区域 HUD 提示 | 纯 quad 叠加，不用着色器，兼容性最好 |
| 第三轮 | 后处理滤镜（含屏幕扭曲） | 需引入 `ShaderGroup` 生命周期 + OptiFine 兼容策略，单独一轮 |
| 待定 | 区域环境音 / 极光 / 视角与镜头 | 取决于定位与晕动症取舍 |

## 二、已核实的 1.7.10 能力清单

| 能力 | 入口 | 核实结论 |
| --- | --- | --- |
| 后处理滤镜 | `net.minecraft.client.shader.ShaderGroup` + `EntityRenderer.theShaderGroup` | `theShaderGroup` 是 **public 字段**，`updateShaderGroupSize(w,h)` 亦 public 且由 `Minecraft.resize` 自动调用 → 自行 `new ShaderGroup(...)` + `createBindFramebuffers(...)` 赋值即可，窗口缩放不会崩。客户端 jar 内自带 20+ 原版 post shader 可作模板：`color_convolve`/`desaturate`/`blur`/`outline`/`pencil`/`ntsc`/`phosphor`/`scan_pincushion`/`fxaa`… |
| 滤镜的作用范围 | `EntityRenderer#updateCameraAndRender` | 在 **`renderWorld` 之后、GUI 之前**生效 → 世界与手部吃滤镜，**HUD 不受影响**（正合预期） |
| 滤镜的两个限制 | — | ① 需 `OpenGlHelper.shadersSupported`；② **与 OptiFine 光影抢同一个槽位（互斥）** |
| 云层接管 | `WorldProvider#setCloudRenderer` | 与 `setSkyRenderer` 并列，写法同构；`RenderGlobal#renderClouds` 开头就查 `getCloudRenderer()` |
| 雨雪接管 | `WorldProvider#setWeatherRenderer` | 同上。注意原版天气是**维度级 + 服务端权威**，区域级只能客户端伪造 |
| 视角 FOV | `FOVUpdateEvent`（Forge） | 1.7.10 的 `EntityViewRenderEvent` **只有** FogDensity/RenderFogEvent/FogColors，**没有** CameraSetup/FOVModifier；FOV 只能走这个事件（public 字段 `newfov`） |
| 镜头抖动/位移 | `RenderWorldEvent` + GL 矩阵 | 没有现成事件，需自己在世界渲染前 `glRotate/glTranslate`（会连世界一起转，符合"镜头晃"的直觉） |
| 屏幕覆盖 | `RenderBlockOverlayEvent` | 可按 `OverlayType`（FIRE/BLOCK/WATER）放行或替换水面/岩浆/失明覆盖 |
| 手部渲染 | `RenderHandEvent` | 可取消或改写第一人称手部/手持物渲染 |
| 方块高亮 | `DrawBlockHighlightEvent` | 区域内高亮特定方块 |
| HUD | `RenderGameOverlayEvent` | 已在用；`Text` 子事件**不受 F3 门控**（已核实），可安全用作字幕层 |
| 音频 | `MovingSound` + `SoundHandler#playSound(ISound)` + `PlaySoundEvent` | 可播放可 tick、可调音量音高的循环音，可替换/屏蔽原版音 |
| 粒子 | 自定义 `EntityFX` 子类 + `effectRenderer.addEffect` | 尘粒已在用；原版每层上限 4000（`EffectRenderer#addEffect`） |

## 三、第一层：同族扩展（复用现有钩子）

- [ ] **光照贴图色调** —— 现在只把亮度映射成单值 L\*；扩成 RGB 三通道 LUT 就能做"黄昏暖光 / 洞穴蓝调 / 水下青绿"
  - 钩子：`LightmapHook`（已在用） ｜ 成本 **低** ｜ 收益 **高**
  - 现成实现里 `BASE_LIGHTNESS` 是一张按通道共用的 LUT，扩成三张即可；`blend`/过渡机制原样复用
- [ ] **氛围粒子**（雪 / 落叶 / 花瓣 / 灰烬 / 火星 / 孢子 / 萤火虫 / 气泡）
  - 钩子：`addEffect`（已在用，尘粒同路） ｜ 成本 **低** ｜ 收益 **高**
  - 一套代码出多种效果：只换粒子外观与运动参数
- [ ] **云层接管**（云色 / 云量 / 云高 / 移动速度）
  - 钩子：`setCloudRenderer` ｜ 成本 **低** ｜ 收益 **中高**
  - 安装-卸载逻辑与现有 `SkyRenderHandler` 完全同构（含"非地表维度不接管"的新约定）
- [ ] **星空日月强化**（星星密度与亮度、日月大小与颜色、流星）
  - 钩子：`setSkyRenderer`（已在用） ｜ 成本 **低** ｜ 收益 **中**
- [ ] **雾形态扩展**（高度雾、雾色随高度/时刻变化）
  - 钩子：`FogColors`/`FogDensity`（已在用） ｜ 成本 **低** ｜ 收益 **中**
  - 高度雾（雾随 y 衰减）对洞穴、山谷、上下层建筑的层次感提升明显

## 四、第二层：新钩子、收益明确

- [ ] **后处理滤镜**（饱和度 / 对比度 / 黑白 / 夜视 / 老电影 / 描边）
  - 钩子：`theShaderGroup` ｜ 成本 **中** ｜ 收益 **高** ｜ 风险：与 OptiFine 互斥
- [ ] **全屏叠加**（暗角 / 覆盖色调 / 血渍 / 扫描线）
  - 钩子：`RenderWorldLastEvent` 或 `RenderGameOverlayEvent`（已在用） ｜ 成本 **低** ｜ 收益 **中高**
  - **不用着色器**（纯 quad + 混合），兼容性最好；暗角是最立竿见影的一个
- [ ] **区域天气**（雨 / 雪 / 沙尘暴）
  - 钩子：`setWeatherRenderer` + 粒子 ｜ 成本 **中** ｜ 收益 **中高**
  - 只能"看起来在下"：管不了真实落雷与积雪
- [ ] **视角与镜头**（FOV 缩放、抖动、下沉、失重错觉）
  - 钩子：`FOVUpdateEvent` + `RenderWorldEvent`(GL 矩阵) ｜ 成本 **中** ｜ 收益 **中高**
  - 风险：**晕动症** —— 建议加客户端开关 + 强度上限
- [ ] **极光**（夜间多层飘带）
  - 钩子：`setSkyRenderer` ｜ 成本 **中** ｜ 收益 **中**
- [ ] **屏幕扭曲**（水下 / 热浪 / 幻境）
  - 钩子：`theShaderGroup` ｜ 成本 **中高** ｜ 收益 **中** ｜ 风险：同 OptiFine 互斥
- [ ] **区域 HUD 提示**（进入标题、危险区红边、准星标记）
  - 钩子：`RenderGameOverlayEvent`（已在用） ｜ 成本 **很低** ｜ 收益 **中**
  - 成本最低的一个，适合顺手做

## 五、第三层：要先定范围

- [ ] **区域环境音 / 区域 BGM**
  - 钩子：`MovingSound` + `SoundHandler` + `PlaySoundEvent` ｜ 成本 **中** ｜ 收益 **高**
  - 仍是纯客户端、不动游戏性，但会让 README 里"纯客户端画面效果"的定位需要改写为"视听"
- [ ] **方块高亮 / 轮廓**（区域内容器、任务点）
  - 钩子：`DrawBlockHighlightEvent` ｜ 成本 **低** ｜ 收益 **低中** ｜ 更偏"功能"而非"效果"
- [ ] **手部 / 手持物处理**（区域内武器发光、手部去饱和）
  - 钩子：`RenderHandEvent` ｜ 成本 **低** ｜ 收益 **低** ｜ 小众，但配滤镜很出效果

## 六、不建议做（避免走弯路）

- **真体积光 / 体积雾**：需要深度缓冲 + 光线步进，1.7.10 固定管线做不到。用"半透明光锥面片 + 加色混合"能伪出七八成观感，成本却只有着色器级。
- **任何改游戏性的效果**（移速、重力、伤害、刷怪、真实光照）：与"纯客户端画面"定位冲突，多人服上客户端伪造还会与服务端判定不一致。
- **依赖 OptiFine 的能力**（OF 的雾控制、OF 光影）：会把模组变成"可选依赖 OF"，且我们与 OF 已经在 `GL_FOG` 开关上打过架。
- **区域级"真实天气"**：天气是维度级、服务端权威，客户端伪造不了落雷与积雪。

## 七、附：新增一种效果的改动清单（本轮修复中确认的扩展点）

1. `common/effect/` 新增 `XxxEffect extends AreaEffect`：实现 `copy()`/`typeId()`/`writeToNbt()`/`writeToBuf()`/`sanitize()` 与访问器；公共参数（权重、过渡时长、生效时段）由基类提供，**不要再各自实现一遍**。
2. `EffectTypes`：加进 `ALL`、`newDefault`、NBT 与 buf 两条读取分支（网络侧统一走 `writeBuf(buf, effect)` 的长度前缀格式，不要自己拼）。
3. `client/effect/` 新增 `XxxEffectRenderer implements EffectRenderer`，并在 `EffectRenderers` 注册。
4. `client/handler/` 如需新的钩子，**先确认落在哪条总线**：`TickEvent`/`PlayerEvent`/`FMLNetworkEvent` 在 FML 总线；`EntityViewRenderEvent`/`RenderXxxEvent`/`PlayerInteractEvent` 在 Forge 总线。挂错 = 静默不触发。
5. `GuiAreas`：详情栏加行位（`SLIDER_TOP + SLIDER_PITCH * n`）并接进 `syncDetailWidgets`/`commitSliderEdits`/`detailWidgets` 三条链。
6. `zh_CN.lang` / `en_US.lang` 各加效果名与参数键。
7. 过渡遵循既有约定：进出"无雾/无染"只动强度；颜色只在效果可见时才过渡；**目标色若来自采样，必须"实时更新但不重启过渡"**（`from` 固定、进度不重置），否则会永远到不了终点。
